### 데이터·판정

1. 현재 누적 거리는 Pleos `Odometer.getCurrentDistanceDriven`의 유효한 수신값(km)과 조회 시각이다. Vehicle SDK 2.3.2 KDoc은 `Current odometer value of the vehicle in kilometers`라고 명시한다. `checkCurrentDistanceDrivenCapabilities`의 READ 계열 지원과 `pleos.car.permission.CAR_DRIVE`를 확인한다. 미지원, 권한 없음(`ERROR_SECURITY_PERMISSION`), `null`/미수신, 실패를 구분한다. 차종명으로 분기하지 않는다. 대상 실차의 초기화·계기판 교체 동작은 확인 필요지만 그 확인 전 계산을 보류하지 않는다.
2. 항목별 마지막 기록은 **교체 시각이 가장 늦은 기록**, 같은 시각이면 **나중에 저장한 기록**이다. 현재 값과 기록 값이 모두 유효하고 현재 값 ≥ 기록 값이면 `경과 거리 = 현재 값 − 기록 거리`를 바로 계산·표시한다. 현재 값 < 기록 값이면 `거리 비교 불가`; 기록은 보존하고 새 기록은 막는다. 원인을 임의 판정하지 않는다.
3. 기준 거리 기본값은 없다. 항목마다 숫자 입력 칸에서 직접 입력하고 100~100,000 km만 저장한다. 최대 6자리이며 범위 밖이면 안내를 강조하고 저장을 비활성화한다. 기준 거리 없이 S04 교체 기록은 저장할 수 있으나 잔여%는 숨긴다.
4. 계산 가능할 때 `실제 잔여% = 100 × max(0, 1 − 경과 거리 / 기준 거리)`. 숫자는 정수 반올림하되 정확히 0·100일 때만 각각 0%·100%, 나머지는 1~99%. 이미지 단계는 반올림 전 값에 `ceil(실제 잔여% / 10) × 10`을 적용한다. 실제 0%만 0% 사진. S01·S05는 같은 판정 결과를 사용한다.
5. 기록 없음·기준 거리 미설정·확인 중·미지원·권한 없음·값 미수신·거리 비교 불가에서는 잔여%/단계 사진 대신 공통 중립 사선 이미지와 해당 문구를 쓴다. 우선 표시 원인은 규제 → 조회 불가/확인 중 → 기록 없음 → 거리 비교 불가 → 기준 거리 미설정 → 정상 순서로 제안한다. 동시 원인의 우선순위는 구현 전 확인 필요.
   - **2026-11-09 변경:** S05 타일과 S01 사진 자리는 위 상태에서 공통 사선 무늬 대신 해당 항목 대표 사진(100% 단계)을 불투명도 40%로 흐리게 표시한다. 잔여%는 숨기고 원인 문구는 그대로 둔다. `consumable_unknown`은 대표 사진이 없는 항목의 대체 이미지로만 쓴다.

### 카탈로그·동력 방식·켜짐

- 카탈로그 18종의 키·이름·묶음은 PLAN.md §3 표를 단일 기준으로 쓴다. 타이어는 1종으로 세지만 위치별 4개 항목으로 기록한다(2026-11-12). 최초 켜짐은 `oil`, `air_filter`, `wiper`, `filter`, `tire_fl`, `tire_fr`, `tire_rl`, `tire_rr`, `brake_pad`. S07에서 변경한 켜짐 값은 로컬에 저장하며 끈 항목의 기록·기준 거리를 지우지 않는다.
- S07 동력 선택의 기본값은 `자동`이다. 자동일 때 AAOS `INFO_FUEL_TYPE`(`android.car.permission.CAR_INFO`) 판정값을 쓴다. `ELECTRIC=10`만 있으면 전기차, 10과 다른 값이 있으면 하이브리드, 그 외 값이 있으면 내연기관, 실패·빈 값이면 확인할 수 없음. 에뮬레이터 v2.1.0의 `[10]`은 전기차로 실측. 사용자가 S07에서 전기차·내연기관·하이브리드를 직접 선택하면 그 값을 동력 필터에 적용한다. VIN은 읽지 않는다.
- 전기차는 내연기관 전용, 내연기관은 전기차 전용을 S05·S02 탭·S07에서 숨긴다. 하이브리드·모름은 모두 보인다. S07의 빈 묶음 제목도 숨긴다. 숨김은 저장값·기록에 영향을 주지 않는다. S02 탭은 켜짐 여부와 무관하게 동력 필터를 통과한 항목을 가로 스크롤로 보여 준다.

### 동작·이벤트 / 접근성 / 구현 메모

- S05 선택 항목을 받는다. `다시 확인`은 capability 확인 후 `getCurrentDistanceDriven` 1회 호출, 응답 수신 시각을 표시한다. 상시 Odometer 리스너는 사용하지 않는다.
- S01-13의 신호 조회는 누적 주행거리와 같은 시점인 화면 진입·복귀·`다시 확인`에서 수행한다. 조회 중에는 이전 신호 값을 유지해 보이지 않는다. 에뮬레이터 v2.1.0은 세 신호 미지원(60001)이므로 카드가 나타나지 않는다. 신호 값으로 교체 시기 해석·권고 문구를 만들지 않는다.
- Gleo `OPEN_CONSUMABLE_RECORD`(activity)로 앱이 열리면 전달된 항목의 S01을 연다. `singleTask` 진입이며 이 차량 동력 방식에 맞지 않는 항목이면 S01로 이동하지 않는다. 주행 규제 중에는 기존 규제 화면이 내용을 가린다. `GET_CONSUMABLE_STATUS`·`LIST_CONSUMABLES_BY_REMAINING`은 화면 전환 없이 음성으로만 답하고 규제 중에는 정차 후 확인을 안내한다. 세부 기능 명세는 [GLEO_ACTIONS.md](../GLEO_ACTIONS.md)를 따른다.
- 사진 대체 텍스트는 `엔진오일, 잔여 60퍼센트, 사진 단계 60퍼센트`처럼 숫자와 단계를 구분한다. 계산 불가는 항목명과 상태만 읽는다.
- 기존 `MainActivity`의 화면/Back 골격, `VehicleGateway`의 지연 생성·해제 경계를 연결점으로 검토한다. 기존 출발 전 점검 화면/로직은 교체 대상이다.
- 비교 불가에서 `기준 다시 잡기`는 확인 대화상자를 거쳐 현재 수신한 누적 거리를 새 기록으로 저장한다. 기존 기록을 덮어쓰거나 자동 연결하지 않는다. S02 이력에는 새 기록을 `기준 다시 잡음`으로 구별해 표시한다. 저장 시점 규제·수신값 재검증의 세부 동작은 코드 확인 필요.

- 값 버튼의 접근성 이름에 증가/감소량과 현재값을 포함한다. 화면 복귀 시 S01·S05의 마지막 기록을 다시 판정한다.

### 알아두기 문구(2026-11-09, S01-11)

- `onStart`: `DrivingRestrictionMonitor`의 규제 리스너 재등록과 초기 상태 반영 → 허용이면 Odometer capability 확인 → `getCurrentDistanceDriven` 조회 → 로컬 기록·기준과 판정. `onStop`: 규제 구독 해제, 응답 무효화, 차량 조회 중지. 규제 변경 콜백에서는 즉시 모든 민감 UI를 숨긴다.

- `PleosApp/README.md`에서 확인한 기존 연결점은 `MainActivity`(Back/화면), `DrivingRestrictionMonitor`(규제 초기값·리스너), `UxRestrictionState`(규제 상태 표현), `VehicleGateway`(Vehicle 지연 생성·해제)다. 기존 출발 전 점검 프로토타입 UI/로직은 교체하고 이 기반만 재사용한다. 코드·리소스 파일은 이 기획에서 수정하지 않는다.

## 확인 필요

- 대상 실차의 주행거리 초기화·계기판 교체 동작, 차량 변경 구분 수단과 실제 값/권한/capability 응답. 유효한 값의 경과·잔여 계산은 보류하지 않는다.
- 628dp 최소 폭에서의 플랫폼별 안전 여백·대비와 버튼 사이 공식 간격. 글자 단계와 버튼 높이 100/80/64dp는 Pleos UI Design Guide 수치다.
- 반실사 3D 일러스트 원본과 198개 단계 이미지의 해상도·압축 품질, 차량 탑뷰 리소스.
- 자동 판정 INFO_FUEL_TYPE 실패 처리와 S07 직접 선택값의 재진입·재시작 보존 동작은 코드 확인 필요.
- S03 시각 증감 폭의 상세 동작, 이력의 나머지 정렬, 동시 상태 원인 우선순위.
- `../tips-sources.md`의 조건부·출처 없음 항목 문구 적합성.
- 로컬 저장의 사용자·차량 경계, 백업 제외, 원본/수정값 보존 정책. 전체 삭제의 기획 범위는 교체 기록과 항목별 기준 거리로 확정했다.
