# Pleos Connect 앱 독립 QA — 이슈 및 검증 기록

최초 작성: 2026-10-27 (KST)  
검토 대상: `PleosApp/` (프로젝트 골격 단계)

## 1. 역할과 기록 원칙

- Codex는 독립적인 QA 담당이다. 제품 코드·설정·Gradle을 직접 수정하지 않는다.
- 이 파일은 Codex가 검증을 마칠 때마다 **직접 갱신**한다(이슈 상태·새 이슈, 규칙은 `.codex/qa.md` 2.2).
- 운전자 주의 분산, 화면·생명주기, 차량 데이터 접근, 오디오, 성능, 보안·개인정보, 심사 제출 관점에서 문제를 찾는다.
- 발견 사항을 문서화한다. 개발자가 수정한 뒤 같은 조건으로 재검증한다.
- 확정된 동작과 원인 추정을 구분한다. 에뮬레이터·실차 미검증 항목을 검증 완료로 표시하지 않는다.
- 문서(`PLEOS_DEV_NOTES.md`)에 없는 사항은 버그로 단정하지 않고 "확인 필요"로 남긴다.

검토 기준: `.claude/skills/pleos-connect-dev/` (SKILL.md Core Rules, cheatsheet.md 위험 신호, 챕터), `PLEOS_DEV_NOTES.md`.

### 상태·우선순위

- **열림**: 수정과 재검증이 남음. **미해결**: 수정 후에도 재검증 기준을 충족하지 못함. **재검증 대기**: 개발 변경은 있으나 테스트가 남음. **해결**: 같은 재현 조건과 관련 검증을 통과함. **해당 없음**: 이슈 전제가 사라짐. **보류**: 사용자 결정으로 재검증을 미룸.
- **P1**: 심사 반려 사유·주행 안전·핵심 흐름 차단. **P2**: 특정 조건에서 기능·데이터가 잘못됨. **P3**: 영향이 제한적인 품질 문제.
- **에뮬레이터 재현**: Pleos Connect Emulator에서 직접 재현. **소스 확인**: 구현과 규칙으로 문제 조건을 확인. 실제 화면 확인은 남음.

### QA-001 (P3) Gleo App Schema의 함수 수 제한 누락 — 상태: 해결
- 위치: `PLEOS_DEV_NOTES.md:169`, `.claude/skills/pleos-connect-dev/chapters/ch02-vehicle-sdk.md:56`, `docs/PLEOS_API_LIST.md:272`
- 재현: 변경된 Gleo Interface 설명에서 `actionCalls`의 함수 수 제한을 찾는다.
- 기대: App Schema 작성 시 호출 가능한 function이 최대 3개라는 제약을 확인할 수 있다.
- 실제: 스키마 파일·승인 흐름만 설명하고 최대 3개 제한은 빠져 있다. 공식 [App Schema Writing Guide](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/app-capability)는 `actionCalls`를 최대 3개로 제한한다.
- 근거 규칙: `.codex/qa.md` 2.6(문서에 없는 사항은 추측하지 않음). 공식 App Schema Writing Guide 2.1, 4절.
- 재검증 기준: 위 세 문서의 Gleo 설명에서 최대 3개 제약을 일관되게 명시하는지 확인한다.
- 한계: 실제 Gleo 승인·호출 동작은 검증하지 않았다.
- **해결(2026-11-10)**: `PLEOS_DEV_NOTES.md`·`chapters/ch02-vehicle-sdk.md`·`docs/PLEOS_API_LIST.md`의 Gleo App Schema 설명 모두에 `actionCalls` 최대 3개 제약이 있음을 확인했다(메인 문서 대조).

### QA-002 (P3) Gleo Callback `data` 형식 누락 — 상태: 해결
- 위치: `PLEOS_DEV_NOTES.md:171`, `.claude/skills/pleos-connect-dev/chapters/ch02-vehicle-sdk.md:58`, `docs/PLEOS_API_LIST.md:276`
- 재현: 변경된 Gleo Callback 설명에서 `response.data`의 필수 여부와 자료형을 찾는다.
- 기대: `data`는 선택 항목이며, 포함할 때 JSON 객체 배열을 담은 **문자열**임을 확인할 수 있다.
- 실제: `PLEOS_DEV_NOTES.md`와 API 목록은 선택 여부만, ch02는 필드 이름만 적어 문자열 형식이 드러나지 않는다. 공식 [Callback Schema Writing Guide](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/action_callback)는 `data`를 선택적 string으로 정의한다.
- 근거 규칙: `.codex/qa.md` 2.6. 공식 Callback Schema Writing Guide 2.1절.
- 재검증 기준: 위 세 문서에서 `data`의 선택 여부와 문자열 형식을 일관되게 명시하는지 확인한다.
- 한계: 실제 broadcast 수신·파싱은 검증하지 않았다.
- **해결(2026-11-10)**: 위 세 문서 모두 `data`가 선택(권장) 항목이며 key-value 객체 배열을 담은 JSON **문자열**임을 명시함을 확인했다(메인 문서 대조).

### QA-003 (P1) 주행 규제 초기값을 얻지 못해도 차량 조회 허용 — 상태: 해당 없음
- 위치: `PleosApp/app/src/main/java/com/pleos/consumables/DrivingRestrictionMonitor.kt:38-47`, `MainViewModel.kt:51-55`
- 재현: `getCarManager()`가 null을 반환하거나 `onStart` 내부에서 예외가 나는 조건에서 화면을 시작한다.
- 기대: 규제 초기값이 확인되기 전에는 정차 중 전용 카드와 차량 조회를 허용하지 않는다.
- 실제: null manager 또는 예외를 `UxRestrictionState.NONE`으로 전달한다. ViewModel은 이를 규제 없음으로 받아 `source.start()`를 호출한다. `Car.createCar()`가 null을 반환할 때는 초기값 전달 없이 화면 기본값의 카드가 보인다. 플랫폼이 실제로 화면을 차단하는지는 미검증이다.
- 근거 규칙: `docs/plan/PLAN.md` 2·5절(초기값 먼저 확인, 규제 중 값 숨김), `.claude/skills/pleos-connect-dev/SKILL.md` Core Rules 3(리스너와 초기값 반영).
- 재검증 기준: 규제 서비스 연결·초기값 조회 실패 시 카드와 차량 조회가 대기 또는 차단되고, 정상 초기값 확인 후에만 조회하는지 확인한다.
- 한계: AAOS 환경에서 서비스 실패·주행 중 실제 화면은 확인하지 못했다.
- **미해결(2026-10-27)**: 서비스·매니저 null 및 예외는 `UNKNOWN`으로 차단하지만, `currentCarUxRestrictions`가 null이면 `UxRestrictionState.from(null)`이 `NONE`을 반환해 `MainViewModel.reconcile()`에서 차량 조회를 시작한다. 초기 화면 상태도 `restricted=false`이므로 초기값 반영 전 카드가 보일 수 있다. 서비스 실패·주행 화면 동작은 미검증이다.
- **재검증 대기(2026-10-27, 2차)**: `DrivingRestrictionMonitor.onStart()`는 서비스·매니저 null, 예외 및 `currentCarUxRestrictions` null을 `UNKNOWN(restricted=true)`으로 전달한다. `MainViewModel`의 초기 상태와 `onScreenStopped()` 후 상태도 `restricted=true`이며, `reconcile()`은 화면 표시 중 규제 없음 초기값을 받은 경우에만 `source.start()`를 호출한다. 실제 서비스 실패·주행 중 화면과 차량 조회는 `adb`를 사용할 수 없어 확인하지 못했다.
- **해당 없음(2026-11-05)**: 출발 전 점검 카드와 `PreDriveCheckSource`가 제거되어 이 이슈의 재현 전제가 사라졌다. 새 앱의 규제·조회 경로는 별도 검토 대상이다.
