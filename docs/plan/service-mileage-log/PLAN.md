# 앱 기획서 (계속 갱신)

> 결정 이력: `DECISIONS.md`. 채택 원안: `../ideas/backlog/2026-10-28-1309-service-mileage-log.md`.
> 상태: **소모품 교체 거리 기록 / Mobility Services / DO 미선언 / 정차 중 전용 / S01~S07 / UI 단계: update** (2026-11-10).

## 1. 주제와 목적

- 소모품을 교체한 시점의 차량 누적 주행거리를 기록하고, 나중에 같은 기준의 차량 값과 비교해 교체 후 경과 거리를 본다. 공개 제목은 임시로 `소모품 교체 거리 기록`을 사용한다.
- 사용자가 관리하는 이력이다. 교체 권장 시기, 정비 필요 여부, 안전 상태를 판정하지 않는다.
- 켜고 차량 동력 방식에 맞는 소모품의 설정한 기준 거리 대비 남은 거리 비율을 잔여%와 사전 제작한 10% 단위 단계 이미지로 표시한다. 이는 사용자가 설정한 거리의 진행 표시이며 정비 판정·교체 권고가 아니다.
- 차량 계측값을 기록에 연결하는 점이 차량 앱의 가치다. 기본 앱과의 기능 중복 여부는 확인 필요다.

## 2. 카테고리 · 사용 범위

- **Mobility Services, DO 미선언(2026-11-10 결정).** 카테고리 예시 "주행과 밀접한 차량 관리 서비스"에 맞춰 Mobility Services로 신청하되, 주행 중 허용 기능은 쓰지 않고 플랫폼이 허용한 Parking에서만 사용한다. 앱이 속도·기어로 주행 가능 여부를 계산하지 않는다.
- 규제 상태 미확인·서비스 없음·주행 규제 시에는 차량 값, 개인 기록, 기록·수정·삭제·갱신 조작을 숨기고 조회를 중단한다. 플랫폼이 앱을 차단하면 플랫폼 화면을 따른다.
- 기준 거리는 정차 중 숫자 키보드로 직접 입력한다. 교체 기록 거리·시각 수정은 기존 큰 증감 버튼을 사용한다. 주행 중 알림·백그라운드 조회는 없다.

### 소모품 카탈로그와 표시

| 묶음 | 키 · 이름 |
|---|---|
| 공통 | `wiper` 와이퍼, `filter` 에어컨 필터, `tire` 타이어, `brake_pad` 브레이크 패드, `brake_disc` 브레이크 디스크, `tire_rotation` 타이어 위치 교환, `alignment` 휠 얼라인먼트, `brake_fluid` 브레이크액, `coolant` 냉각수, `battery` 12V 배터리 |
| 내연기관 | `oil` 엔진오일, `air_filter` 엔진 에어필터, `spark_plug` 점화 플러그, `drive_belt` 구동 벨트, `transmission_oil` 변속기 오일, `fuel_filter` 연료 필터 |
| 전기차 | `reduction_oil` 감속기 오일, `battery_coolant` 배터리 냉각수 |

- 최초 켜짐은 `oil`, `air_filter`, `wiper`, `filter`, `tire`, `brake_pad` 6종이다. S07에서 줄 전체 또는 스위치를 눌러 변경한다. 끈 항목의 기록과 기준 거리, 켜짐 값은 보관한다.
- 앱 시작 때 AAOS `INFO_FUEL_TYPE`을 한 번 읽는다. 값이 `ELECTRIC=10`만 있으면 전기차, 10과 다른 값이 함께 있으면 하이브리드, 10이 없고 다른 값이 있으면 내연기관, 실패·빈 값이면 `확인할 수 없음`이다. 전기차에서는 내연기관 전용, 내연기관에서는 전기차 전용 항목을 S05·S02 탭·S07에서 숨긴다. 하이브리드·모름은 모두 표시한다. 빈 묶음 제목도 숨긴다. VIN은 읽지 않는다. 에뮬레이터 v2.1.0에서 `INFO_FUEL_TYPE=[10]`→전기차를 실측했다.
- S05는 켜짐과 동력 필터를 모두 통과한 항목을 아래 zone 순서와 각 묶음의 카탈로그 순서로 왼쪽·오른쪽 열에 번갈아 놓는다. 각 열은 세로 가운데 정렬하고 넘치면 스크롤한다. 0개면 `설정에서 소모품을 켜세요`를 표시한다.

| 홈 zone 순서 | 소모품(묶음 안의 카탈로그 순서) |
|---|---|
| 앞 | 엔진오일, 엔진 에어필터, 와이퍼, 브레이크액, 냉각수, 12V 배터리, 점화 플러그, 구동 벨트 |
| 실내 | 에어컨 필터 |
| 바퀴 | 타이어, 브레이크 패드, 브레이크 디스크, 타이어 위치 교환, 휠 얼라인먼트 |
| 하부 | 변속기 오일, 연료 필터, 감속기 오일, 배터리 냉각수 |
| 뒤 | 없음 |

- **조회 실패:** 미지원(capability 없음), 권한 없음, 값 미수신·오류를 구분한다. 값을 못 읽으면 새 기록을 저장할 수 없고, 이전 기록을 현재 값처럼 표시하지 않는다.
- **기록 없음:** 항목별 `기록 없음`으로 표시한다. 더미 수치·사용자 수동 주행거리 입력은 쓰지 않는다.
- **S05 아이콘·S01 상세:** S05는 탑뷰 좌우 열의 보이는 항목 아이콘 옆에 상태를 표시한다. S01은 선택한 한 항목만 보여 준다. 계산 가능하면 교체 후 경과 거리를, 불가하면 마지막 교체 거리·시각·출처를 표시한다. 기록이 없을 때 수치를 만들지 않는다.
- **기준 거리·잔여 표시:** 공식 적용 수치가 확인되기 전에는 항목별 참고 기본값을 넣지 않는다. 사용자가 첫 교체 기록 저장 흐름(S04 또는 S06)에서 숫자 입력 칸으로 기준 거리 `100~100,000 km`를 직접 설정하고, 이후 정차 중 S06에서 수정한다. 입력은 최대 6자리이며 범위 밖이면 안내 문구를 강조하고 저장을 비활성화한다. 기준 거리와 유효한 경과 거리가 모두 있을 때만 `실제 잔여% = 100 × max(0, 1 − 교체 후 경과 거리 / 기준 거리)`로 계산한다. 숫자 표시값은 정수 반올림하되 실제 값이 정확히 0%·100%일 때만 각각 0%·100%를 표시하고, 그 사이는 1~99%로 제한한다. 사진 단계는 **반올림 전 실제 잔여%**에 `ceil(실제 잔여% / 10) × 10`을 적용한다. 실제 0%일 때만 0% 이미지(전체 흑백·밝기 40%), 1~10%는 10%, 11~20%는 20%, …, 91~100%는 100% 이미지다. 숫자 잔여%와 이미지 단계가 다를 수 있다. 0% 문구는 `설정한 거리에 도달했습니다`다. 와이어프레임에는 `[사진 · 단계 N%]`로 표시한다.
- **단계 이미지 제작:** Codex 이미지 생성으로 항목별 반실사 3D 일러스트 원본 `docs/assets/consumables/<키>.webp` 18장을 만든다. 각 원본에서 잔여 단계 N%마다 위쪽 `100−N%`를 흑백으로 바꾸고 밝기를 40%로 낮춰 어둡게 덮는다. 어두운 부분과 원본 부분의 경계에는 얇은 밝은 선을 넣어 원래 무채색인 소모품도 단계를 구분할 수 있게 한다. 10% 단위 `res/drawable-nodpi/<키>_NNN.webp` 11장(100~000)을 사전 제작하며, 100%는 어두운 부분이 없고 0%는 전체가 어둡다. 총 198장이다. 큰 사진/작은 아이콘은 같은 단계 판정을 쓴다. 해상도·압축 품질은 확인 필요다.

| 구분 | 원본 | 앱 이미지 | 수량 |
|---|---|---|---|
| 18종 전체 | `docs/assets/consumables/<키>.webp` | `res/drawable-nodpi/<키>_{100,090,080,070,060,050,040,030,020,010,000}.webp` | 18×11=198장 |
| 계산 불가 공통 | — | 벡터 `consumable_unknown` | 1개, 198장과 별도 |

- **계산 불가 이미지:** 기록 없음·거리 비교 불가·값 미수신·미지원·권한 없음·기준 거리 미설정·확인 중에는 잔여%를 숨기고 공통 중립 사선 무늬 벡터 `consumable_unknown`과 해당 상태 문구를 표시한다. 기준 거리 미설정 문구는 `기준 거리를 설정하세요`다.
- **기본값 출처 검토(2026-10-28):** 당시 엔진오일·타이어·실내 필터의 차종별 공식 자료를 검토했다. 공통 교체 거리로 적용할 수 없어 18종 모두 기준 거리 기본값을 비워 둔다. 사용자 입력값은 정비 권고가 아니다.

- **조회 시점:** 진입·복귀·수동 갱신 시점의 값이며 실시간 수치로 표현하지 않는다. 타이머·폴링·백그라운드 수집은 없다.
- **현재 값이 기록보다 작음:** 현재 값이 기록보다 작으면 `거리 비교 불가`로 표시하고 경과 거리를 계산하지 않는다. 차량 변경·계기판 교체·주행거리 초기화를 구분할 수단이 확인될 때까지 이 상태에서 새 교체 기록 저장을 막고 짧은 이유를 표시한다. 기존 기록은 지우거나 새 차량 값에 자동 연결하지 않으며, 정차 중 열람·수정·삭제는 유지한다. 원인을 임의 판정하지 않는다.
- **단일 기기 저장:** 화면에 공유 안내 문구는 두지 않는다(2026-11-09 사용자 결정). 사용자·차량 분리 수단이 확인되지 않으면 이 범위를 넘겨 저장·공유하지 않는다. S02에서 전체 삭제 시 모든 교체 기록과 항목별 기준 거리도 지워지며 되돌릴 수 없음을 확인한다.
- **수정 기록 출처 정책 제안:** 최초 차량 수신 기록과 사용자 수정 기록을 구분한다. 거리 또는 시각을 한 번이라도 고치면 S01·S02·S03의 해당 기록과 이를 기준으로 한 경과 거리에 `사용자 수정 · 차량 계측값 아님`을 붙인다. 수정 전 원본 차량값·수신 시각과 수정 시각을 보존하는 안을 제안한다. 원본/수정값의 실제 보존·백업 정책은 확인 필요다. 수동 수정값을 현재 차량 계측값으로 재사용하지 않는다.
- **정차 중 입력:** S03에서 거리는 고정 폭 100 km의 큰 `−/+` 버튼, 시각은 날짜·시·분별 큰 `−/+` 버튼을 사용한다. 키보드·길게 누르기 반복 입력은 두지 않는다. 수정 가능 범위와 시각 증감 폭은 확인 필요다. 저장 전 변경값·출처와 마지막 기록 기준 변경 가능성을 보여 준다.

## 4. 화면 흐름

1. **S05 진입:** 규제 허용 확인 전에는 정차 안내만 표시한다. 허용되면 차량 값·로컬 기록을 읽고 켜짐·동력 필터를 적용한다. 1칸/2칸 모두 탑뷰 좌우 열에 zone 순으로 항목을 번갈아 놓고 세로 가운데 정렬하며 넘치면 스크롤한다. 2칸 오른쪽에는 미선택 시 `소모품을 선택하세요`를 표시한다. 켠 항목이 없으면 `설정에서 소모품을 켜세요`를 표시한다. 오른쪽 위 `설정`→S07.
2. **S05 선택 → S01 상세:** portrait는 사진 아이콘 선택 시 S01로 전환하고 Back은 S05로 간다. landscape는 선택 아이콘을 강조하고 오른쪽에 같은 S01 내용을 표시한다. S05의 세 사진 아이콘은 항목별 잔여 상태를 요약한다. S01은 큰 사진·잔여%·기준 거리와 `기준 거리 수정`(S06), 현재 누적 거리·조회 시각, 교체 후 경과 거리, 마지막 교체 거리·시각·출처, `교체 기록`(S04)·`이력`(해당 항목 S02)·`다시 확인`을 둔다. 0%에는 `설정한 거리에 도달했습니다`를 표시한다. 계산 불가 시 공통 중립 이미지와 마지막 교체 거리 또는 `기록 없음`을 표시한다. 확인 중·미지원·권한 없음·값 미수신·거리 비교 불가 시 새 기록을 막고 이유를 표시하되 이력·기준 거리 수정 접근은 정차 중 유지한다. S05 아이콘과 S01 상태 판정은 같다.
3. **새 기록:** S01의 `교체 기록`에서 S04로 이동해 선택 항목·실제 차량 수신 거리·조회 시각을 확인한다. 해당 항목에 기준 거리가 없으면 S04에서 S06 첫 설정으로 이동해 숫자로 100~100,000 km 값을 입력한 뒤 S04로 돌아온다. 기준 거리 미설정 자체는 차량 교체 기록 저장을 막지 않으며, 저장 후 잔여%만 보류한다. 정차 허용·실제 유효한 값 수신이 저장 시점에도 유지되고 거리 비교 불가가 아니면 저장한다. 상태가 바뀌면 저장을 막는다. 취소/Back은 저장 없이 S01로 돌아가며 과거 기록은 보존한다.
4. **S02 항목별 이력:** S01의 선택 항목을 먼저 표시하고 보이는 항목만 가로 스크롤 탭으로 전환한다. 끈 항목도 동력 필터에서 보이면 탭에 포함한다. 기록별 수정(S03)·삭제, 전체 삭제를 제공한다. 전체 삭제는 숨긴 항목까지 모든 기록과 기준 거리를 지운다. landscape는 왼쪽 안내·전체 삭제, 오른쪽 목록이다. 나머지 정렬 방식은 확인 필요다.
5. **S03 기록 수정:** 기록 거리와 시각을 편집한다. 저장 전에 변경 전후와 기준 기록 변경 가능성을 확인 대화상자에 보여 주고 `계속 수정`/`변경 저장`을 제공한다. landscape는 왼쪽 조작, 오른쪽 전후 비교다. Back은 저장하지 않고 S02로 돌아간다.
6. **S04 새 기록 확인:** 항목·차량에서 수신한 거리·그 조회 시각을 표시하고 `기록 저장`과 `취소`를 제공한다. 첫 기준 거리 미설정이면 `기준 거리를 설정하세요`와 S06 진입을 제공한다. S06에서 저장해 돌아오거나, 기준 거리 없이 교체 기록만 저장할 수 있다. 차량값 미수신·권한/지원/규제 상태 변화 또는 `거리 비교 불가` 상태 진입 시 기록 저장을 막는다. 비교 불가 시에는 짧은 이유를 표시한다. S04는 수동 차량 거리 입력을 제공하지 않는다.
7. **제한·숨김·복귀:** S01~S07 모두 규제 상태 미확인·주행 규제 시 차량 그림·값·기록·조작을 숨기고 `정차 중에만 사용할 수 있습니다`만 표시하며 진행 중 응답을 무효화한다. S05 최상위 Back은 앱을 숨긴다. 복귀 시 규제 상태를 먼저 확인하고 현재 차량 값을 재조회한다.
8. **S06 기준 거리 설정·수정:** S01의 선택 항목 또는 첫 기록 S04에서 진입한다. 기본값은 비워 두고 기존 값이 있으면 숫자 입력 칸에 표시한다. 숫자 키보드·최대 6자리·힌트 `예: 10000`·단위 km로 직접 입력한다. `100~100,000 km` 밖이면 `range_hint`를 강조색으로 표시하고 저장을 비활성화한다. 키보드 완료 키는 유효값일 때 저장한다. 전체 화면 입력 모드는 끄고 앱 화면을 유지한다. 화면 이탈·주행 규제 시 키보드를 닫고, 규제 상태 미확인·주행 규제 시 값·조작을 숨긴다. 저장 후 진입 화면(S01 또는 S04)으로 돌아가며 S01·S05 잔여 표시를 다시 판정한다. Back/취소는 저장 없이 진입 화면으로 돌아간다.

9. **S07 소모품 설정:** S05 설정에서 진입한다. 뒤로는 S05. 안내 `켠 항목만 홈 화면에 보입니다…`, 차량 동력, 묶음별 대표 100% 이미지·이름·스위치 행을 표시하고 전체 행 탭을 허용한다. 동력 필터로 보일 행이 없는 묶음 제목도 숨긴다. 끄더라도 기록·기준 거리·켜짐 값은 유지한다.

## 5. 데이터 · 기술 경계

- 메인이 확인한 Vehicle SDK 2.3.2 소스 jar의 `Odometer.kt`·`OdometerImpl.kt`·`DistanceDrivenListener.kt` 기준: 기본 경로는 Pleos `Odometer.getCurrentDistanceDriven(onComplete: (Float?) -> Unit, onFailed)`이다. KDoc상 현재 누적 거리 단위는 km이고 값은 `Float?`(없으면 `null`)이다. capability 함수는 `checkCurrentDistanceDrivenCapabilities`, 리스너 함수는 `registerDistanceDriven`/`unregisterDistanceDriven`이다. MVP는 화면 진입·복귀·수동 갱신 시 조회하며 상시 리스너는 쓰지 않는다.
- 해당 조회·capability·리스너 인터페이스의 `@RequiresPermission`과 구현의 `@RequiresCustomPermission`은 모두 `pleos.car.permission.CAR_DRIVE`이고 KDoc에는 protection level `normal`로 표기되어 있다. 이 함수들에는 PRIVATE 권한 불일치가 없다. 지원 여부를 capability로 확인하고 차종명으로 가르지 않는다. 권한 오류와 미지원·통신 실패·`null` 값을 구분한다.
- Pleos 내부 속성은 `PleosPropertyIds.PERF_ODOMETER`(GLOBAL)이다. 2026-10-28 Pleos 에뮬레이터 v2.1.0의 Virtual Console(`/vehicle/catalog`)에서 `Odometer`(`perf-odometer`)가 AAOS 표준 `PERF_ODOMETER`(`0x11600204`, system, area 0)에 연결된 것을 메인이 확인했다. 콘솔 기준 단위는 km, 범위는 0~1,000,000, step은 1, 쓰기 경로는 `/vehicle/odometer`다. 에뮬레이터에서는 Pleos Odometer와 표준 속성에 같은 값이 공급되는 것으로 보인다. 대상 차량에서의 동일성 및 표준 경로의 서드파티 접근 권한은 확인 필요다. 표준 경로를 기본 경로로 가정하지 않는다.
- 같은 콘솔의 `/vehicle/state`에서 `odometer.traveled_distance_km`는 `0.0`, `source`는 `default`, `emulator_active`와 `bridge_ready`는 모두 `false`였다. 아직 값이 발행되지 않은 상태이므로 앱 조회에서 `null`·미수신이 나올 수 있다. adb `cmd car_service get-property-value`는 `requires non-user build`로 거부되고 VHAL `dumpsys`는 `FAILED_TRANSACTION`이므로 이 에뮬레이터에서 adb 경로로 값은 읽지 못했다. 콘솔의 거리 값을 낮추어 `현재 값 < 기록 거리 → 거리 비교 불가` 상태를 시험할 수 있다.
- 기록에는 항목, 교체 시점에 수신한 값, 단위·기준을 검증할 수 있는 정보, 기록 시각, 출처 상태(차량 수신/사용자 수정)를 담는 안을 검토한다. 원본 값·수신 시각·수정 시각 보존을 제안한다. 사용자·차량 분리 수단이 확인되지 않으면 기기 로컬 단일 기록만 제공하고 전체 삭제를 지원한다. 실제 저장 경계와 백업 제외 수단은 확인 필요다.
- Vehicle SDK 2.3.2 `getCurrentDistanceDriven` KDoc은 `Current odometer value of the vehicle in kilometers`로 현재 값의 의미와 km 단위를 명시한다. 현재 값과 마지막 기록 값이 모두 유효하고 현재 값 ≥ 기록 값이면 경과 거리와 설정된 기준 거리 대비 잔여%를 바로 계산·표시한다. 현재 값 < 기록 값이면 `거리 비교 불가`이며 계산하지 않는다. 대상 차량 누적 기준 확인 전 계산 보류 조건은 두지 않는다.

## 6. MVP 범위 밖

- 앱의 교체 권장·정비 알림·진단·안전 점수, 자동 교체 판정, 차량 제어, 운행 중 접근. 사용자 기준 거리의 진행 표시와 항목별 사전 제작 단계 사진 11장 선택은 범위에 포함하되 권고로 해석하지 않는다. 사진 위 실시간 회색 덮개 렌더링은 범위에서 제외한다.
- 계정·클라우드 동기화·공유, 위치, 음성, 외부 정비소 연동, 백그라운드 조회·폴링.
- 새 기록을 만들 때 주행거리 수동 입력으로 차량값을 대체하는 기능, 차종명별 예외 처리. 기존 기록의 오입력 정정은 허용한다.

## 7. 위험 · 확인 필요

- **에뮬레이터 실측:** Virtual Console 카탈로그에서 Pleos Odometer와 AAOS 표준 `PERF_ODOMETER`의 연결이 확인되었다. `/vehicle/state`는 값 미발행 상태이며, adb의 `car_service`·VHAL `dumpsys` 조회는 각각 빌드 제한·`FAILED_TRANSACTION`으로 실패했다. 콘솔에서 현재 값을 기록보다 낮추는 비교 불가 시험은 가능하다. 이는 앱 API 응답이나 대상 차량 동작을 입증하지 않는다.
- **확인 필요:** 대상 실차의 주행거리 초기화·계기판 교체 시 값의 동작과 차량 변경을 구분할 공식 수단, 실제 1칸·2칸 화면 크기 및 UI Design Guide의 터치·글자·대비 수치. 값 감소 시 비교 불가·기록 보존 정책은 결정되었다. 이 확인은 유효한 값의 경과·잔여 계산 표시를 보류하지 않는다.
- **구현 단계에서 확인 가능:** 앱의 `getCurrentDistanceDriven`·`checkCurrentDistanceDrivenCapabilities` 실제 응답(`null`·미수신·권한 거부·미지원·오류 포함), 대상 차량에서의 속성 동일성과 App Market 승인. 값이 없으면 새 기록 저장과 경과 거리 계산을 막는다.
- **확인 필요:** 차량 변경·계기판 교체·주행거리 초기화를 구분할 공식 수단. 수단 확인 전 `거리 비교 불가` 상태에서는 새 교체 기록 저장을 막고, 기존 기록은 정차 중 열람·수정·삭제할 수 있다. 구분 수단 확인 뒤 기록 간 연결·분리 방식은 그 근거에 따라 다시 결정해야 한다.
- **확인 필요:** 공유 차량의 로컬 데이터 사용자별·차량별 분리 가능성, 실제 저장 범위·백업 제외 방법, 기본 앱의 사용자 지정 소모품 기록 지원 여부. 기획상 전체 삭제 범위는 모든 교체 기록과 항목별 기준 거리로 확정했다.
- **구현 단계에서 확인 가능:** 성능 한도(RAM 400MB, 실행 10초 등)는 구현 시 검증한다.
- **확인 필요:** 항목별 공식 적용값의 차종·연식·지역·운행 조건. 기준 거리는 사용자 직접 입력값이며 정비 권고가 아니다. 반실사 3D 원본과 단계 이미지의 해상도·압축 품질, 탑뷰 리소스·실차 표시를 확인한다.

2. ~~재기록~~ **결정: B 전체 이력 보유, 항목의 마지막 기록으로 경과 거리 계산.**
3. ~~잘못 저장한 기록~~ **결정: B 거리·시각 직접 수정 허용.** 출처 표기와 증감 버튼 입력은 §3 제안.
4. ~~분리 수단 부재 시~~ **결정: B 단일 기기 기록, 공유 안내와 전체 삭제.**
5. ~~마지막 기록 순서~~ **결정: B 사용자가 기록한 교체 시각 순서.** 시각 수정으로 기준 기록이 바뀔 수 있음을 S03 확인 단계에 표시한다. 동일 시각인 기록은 질문 8의 결정을 따른다.
6. ~~수정 거리 증감 방식~~ **결정: B 고정 폭 ± 버튼, 폭 값 B 100 km.** 수정 가능 범위 확인 필요.
7. ~~새 기록 저장 전 확인~~ **결정: A 항목·차량 수신 거리·조회 시각을 S04에서 확인한 뒤 저장.**
8. ~~동일 교체 시각의 기준 기록~~ **결정: A 그중 나중에 저장한 기록.**
9. ~~차량 변경·계기판 교체·주행거리 초기화를 구분할 수 없을 때의 정책~~ **결정: A 기존 기록과 새 차량 값을 자동 연결하지 않음.** 현재 값 < 기록 거리이면 `거리 비교 불가`, 경과 거리 미계산, 기록 보존.
10. ~~비교 불가 상태의 새 기록~~ **결정: A 차량 변경·계기판 교체·주행거리 초기화를 구분할 수단이 확인될 때까지 저장 중지.** 기존 기록 열람·수정·삭제는 정차 중 유지한다.
11. ~~계산 불가 사진 표시~~ **결정: A 중립 사선 무늬 + 상태 문구.** 잔여%는 숨긴다.
12. ~~적용 차량·기본값 출처~~ **결정: B 공식 적용값 확인 전 기본값 비움.**
13. ~~첫 기준 거리 입력~~ **결정: 첫 교체 기록 저장 흐름에서 S06 숫자 입력으로 직접 설정.** 2026-11-05 결정이 기존 프리셋·고정 폭 ± 방식을 대체한다.
14. ~~구체 프리셋 수치~~ **대체됨(2026-11-05): 프리셋을 제공하지 않고 사용자가 직접 숫자를 입력한다.**
15. ~~기준 거리 최솟값·최댓값~~ **결정: 100~100,000 km 유지.** 범위 밖 입력은 안내를 강조하고 저장을 비활성화한다.
16. ~~잔여% 표시 반올림~~ **결정: A 정수 반올림.** 실제 값이 정확히 0%·100%일 때만 0%·100%를 표시하고, 중간 값은 1~99%로 제한한다. 전체 흑백·밝기 40% 이미지는 실제 0%일 때만 적용한다.
17. ~~계산 불가·기준 거리 미설정의 중립 사선 무늬 별도 이미지~~ **결정: 공통 벡터 `consumable_unknown` 1개.** 사진이 아닌 사선 무늬이며 항목명으로 구분한다. 18종에 공통 사용한다.
18. ~~전체 삭제에 기준 거리 포함 여부~~ **결정: B 모든 교체 기록과 항목별 기준 거리 삭제.** S02 확인 대화에 범위와 되돌릴 수 없음을 명시하고 삭제 후 S01·S05를 재판정한다.
19. ~~대상 차량 누적 기준 확인 전 경과·잔여 계산 보류~~ **변경: 보류 조건 제거.** Vehicle SDK 2.3.2 KDoc을 근거로 두 값이 유효하고 현재 값 ≥ 기록 값이면 바로 계산·표시한다. 실차 초기화·계기판 교체 동작은 확인 필요다.
